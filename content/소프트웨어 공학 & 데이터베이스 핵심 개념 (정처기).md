
#개발기초 

소프트웨어를 기획하고 만드는 과정은 거대한 건축물을 짓는 현장의 공정 관리와 놀랍도록 닮아 있다. 정보처리기사 필기시험의 핵심이자, AI에게 바이브코딩을 지시할 때 반드시 알아야 하는 시스템의 뼈대 개념들을 정리한다.

## 1. 소프트웨어 생명주기 (SDLC) : 건물이 지어지는 5단계
소프트웨어도 처음 기획부터 폐기될 때까지의 생명 주기가 있다. (요구사항 분석 ➔ 설계 ➔ 구현(시공) ➔ 테스트(감리) ➔ 유지보수) 이 주기를 관리하는 대표적인 두 가지 방법론이 있다.



[Image of Waterfall vs Agile software development lifecycle]


* **폭포수 모형 (Waterfall Model):**
    * **방식:** 한 단계가 완벽히 끝나야만 다음 단계로 넘어가는 가장 전통적인 방식.
    * **현장 비유:** 대규모 토목/건축 공사와 같다. 설계도가 완벽히 확정되고 승인되어야 시멘트를 붓기 시작한다. 중간에 고객이 요구사항을 바꾸면 현장이 마비되듯 유연성이 떨어진다.
    * **특징:** 매 단계마다 확실한 문서(산출물)가 남기 때문에 일정 관리가 편하다.
* **애자일 모형 (Agile Model):**
    * **방식:** 처음부터 완벽한 건물을 짓는 대신, 핵심 기능만 있는 작은 가건물을 먼저 짓고 고객 반응을 보며 계속 수정·추가해 나가는 현대적인 방식.
    * **현장 비유:** 모델하우스 거실만 먼저 꾸며서 피드백을 받고, 그다음 안방을 꾸미는 식이다. 
    * **특징:** 바이브코딩이나 스타트업에서 가장 선호하는 유연한 방식이다. (스크럼, 칸반 등이 여기에 속함)

## 2. 3계층 구조 (3-Tier Architecture) : 시스템의 3대 부품
어떤 웹사이트든, 앱이든 결국 이 3가지 덩어리가 맞물려 돌아간다. 각 계층은 철저하게 분리되어(독립성) 한 곳을 수리할 때 다른 곳에 영향을 주지 않아야 한다.



* **프론트엔드 (Client / 클라이언트):** * 건물의 외관, 인테리어, 로비 안내 데스크. 사용자의 눈에 보이고 직접 클릭하는 모든 화면이다. (HTML, CSS, JavaScript)
* **백엔드 (Server / 서버):** * 보이지 않는 곳에서 돌아가는 건물의 배관, 전기 시설, 엘리베이터 모터. 버튼을 누르면 실제로 데이터를 연산하고 처리하는 로직을 담당한다. (Python, Java 등)
* **데이터베이스 (DB / Database):** * 건물의 지하 창고이자 거대한 엑셀 장부. 회원 정보, 업로드한 파일 등이 안전하게 보관되는 곳이다.

## 3. 데이터베이스와 SQL : 창고 관리 비법
현대 시스템의 90% 이상은 표(Table) 형태의 **관계형 데이터베이스(RDBMS)**를 사용한다. 
이 창고에 데이터를 넣고 빼려면 창고 관리인에게 정확한 명령어를 내려야 하는데, 이 언어가 바로 **SQL(구조화된 질의어)**이다.

### 🔑 SQL의 4대 기본 동작 (CRUD)
기획안을 작성할 때 "이 데이터는 어떻게 처리할까?"를 결정하는 4가지 기준이다.
1. **C**reate (`INSERT`) : 새로운 데이터 입고 (생성)
2. **R**ead (`SELECT`) : 조건에 맞는 데이터 찾기 (조회) - *가장 많이 쓰임*
3. **U**pdate (`UPDATE`) : 기존 데이터 수정
4. **D**elete (`DELETE`) : 불필요한 데이터 폐기 (삭제)

### 👑 기본키 (Primary Key, PK)의 개념

* **정의:** 엑셀 표에서 여러 줄(행)의 데이터가 있을 때, **각 데이터를 절대 헷갈리지 않고 정확하게 식별할 수 있는 유일한 고유 번호.**
* **필수 조건:** 값이 텅 비어있으면 안 되고(`Not Null`), 절대 다른 데이터와 중복되면 안 된다(`Unique`).
* **예시:** 동명이인이 있을 수 있는 '이름'은 기본키가 될 수 없다. '주민등록번호', '사번', '프로젝트 고유 ID' 등이 완벽한 기본키다. 
* **바이브코딩 팁:** AI에게 데이터베이스 설계를 지시할 때, "이 테이블의 기본키(PK)는 뭘로 할까?"를 명확히 정해주면 오류를 획기적으로 줄일 수 있다.
