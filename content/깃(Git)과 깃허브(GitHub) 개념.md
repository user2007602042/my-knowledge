#개발기초 
## 1. Git이란 도대체 무엇인가?
Git은 단순한 개념이 아니라, 컴퓨터에 설치해서 사용하는 **'버전 관리 소프트웨어(VCS)'**다. 파일의 수정 내역을 시간순으로 사진 찍듯 저장(스냅샷)하여, 언제든 과거의 특정 시점으로 되돌릴 수 있게 해주는 **'파일의 시간 여행 장치'**이자 꼼꼼한 **'작업 장부'** 역할을 한다.

* **CLI (Command Line Interface):** 마우스(GUI) 대신 까만 터미널 창에서 텍스트(명령어)를 쳐서 Git에게 작업을 지시하는 방식. 속도가 압도적으로 빠르고 기록이 명확히 남아 개발 실무에서 필수로 사용된다.
* **내 컴퓨터 안의 비밀 장부:** `npx quartz sync` 같은 명령어를 치면, 백그라운드에 숨어있던 Git 프로그램이 몰래 작동하여 `.git`이라는 숨김 폴더(로컬 저장소)에 모든 변경 내역을 기록한다.

## 2. Git vs GitHub: 완벽한 차이점
가장 많이 헷갈리는 두 가지는 완전히 다른 역할을 한다.

* **Git (로컬 저장소):** 내 컴퓨터 안에서 오프라인으로 작동하는 '장부 프로그램'이자 개인 작업실. 인터넷이 끊겨도 작업하고 버전을 기록할 수 있다.
* **GitHub (원격 저장소):** Git으로 기록한 장부와 파일들을 인터넷에 백업하고 공유할 수 있는 '온라인 클라우드(메인 서버)'. 다른 사람과 협업할 때 완성된 결과물을 올려두는 본사 창고 역할을 한다.

## 3. 정석적인 Git 작업 흐름 4단계
여러 명이 하나의 메인 서버(GitHub)를 두고 협업할 때 반드시 거쳐야 하는 필수 프로세스다.

1. **Fetch (확인):** "서버(창고)에 다른 사람이 새로 올려둔 업데이트가 있나?" 변경 내역의 목록만 훑어보는 단계. 내 파일은 변하지 않는다.
2. **Pull (가져와서 합치기):** 서버에 있는 최신 버전을 내 컴퓨터로 다운로드하여, 현재 내 도면(작업물)과 병합하는 단계. **(작업 시작 전 필수!)**
3. **Commit (포장 및 메모):** 내 컴퓨터에서 파일 수정을 마친 뒤, "무엇을 수정했는지" 꼬리표(메시지)를 붙여 하나의 버전으로 확정 짓는 단계. (아직 내 컴퓨터 안에만 존재함)
4. **Push (서버로 배송):** 완벽하게 포장된(Commit) 내 작업물을 비로소 인터넷 메인 서버(GitHub)로 쏘아 올려서 모두가 볼 수 있게 업데이트하는 마지막 단계.

## 4. 동시 작업 원리 (구글 시트 vs Git)
* **구글 스프레드시트 (실시간 중앙 집중식):** 여러 명이 하나의 큰 종이에 동시에 달라붙어 펜을 들고 실시간으로 글을 쓰는 방식. 내가 쓰는 내용이 0.1초 만에 남에게도 보인다.
* **Git (비동기 분산식):** 각자 원본 도면을 복사해 자기 방(로컬 저장소)으로 들고 가 철저히 격리된 상태로 작업한다. 작업이 다 끝나면 나중에 본사(서버)에 결과물을 제출하여 통합한다. 코드는 한 줄만 꼬여도 치명적이기 때문에 이 방식을 쓴다.

## 5. 브랜치(Branch)와 충돌(Conflict) 관리
* **Branch (가지치기):** 메인 도면(본동)은 안전하게 보존한 채, 새로운 아이디어나 기능을 테스트하기 위해 뻗어 나온 '안전한 복사본 도면(별동)'. 작업이 성공적으로 끝나면 메인 도면과 합치고(Merge), 실패하면 가지만 잘라버리면 된다.
* **Merge Conflict (병합 충돌):** 두 명의 작업자(A와 B)가 도면의 '완전히 똑같은 줄'을 각자 다르게 수정했을 때 발생하는 현상.

### 🚨 충돌(Conflict)이 발생했을 때의 해결 원칙
Git은 코드가 망가지는 것을 막기 위해 임의로 남의 코드를 덮어쓰지 않는다. A가 먼저 서버에 올린 상태에서 B가 `Pull`을 하면, Git은 비상정지 후 B에게 결정권을 넘긴다.

1. **수동 편집:** 파일 안에 A의 코드와 B의 코드가 동시에 구겨져 들어간다. B는 파일을 열어 눈으로 확인하고, 불필요한 코드를 직접 지워서 최종본을 결정해야 한다.
2. **병합 커밋 (Merge Commit):** 눈으로 확인하고 합의를 마쳤다는 증거로 새로운 포장(Commit)을 한 번 더 거쳐야 한다.
3. **재전송 (Push):** 합의된 새로운 커밋을 만들고 나서야 비로소 서버에 업데이트(`Push`)가 허락된다. (※ 남의 코드를 묻지도 따지지도 않고 날려버리는 '강제 푸시(Force Push)'는 실무 금기 사항이다.)
