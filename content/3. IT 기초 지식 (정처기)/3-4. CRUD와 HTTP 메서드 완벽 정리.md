#개발기초 

웹 개발에서 데이터를 다룰 때 가장 많이 듣게 되는 두 가지 용어 그룹이 있다. 하나는 **CRUD**이고, 다른 하나는 **HTTP 메서드(Method)**다. 이 둘은 서로 밀접하게 연결되어 있지만, 사용하는 '맥락'이 다르다.

## 1. 관점의 차이: 개념 vs 통신 수단

* **CRUD (개념적 용어 / 데이터베이스 관점):**
  * "데이터를 가지고 할 수 있는 4가지 기본 행동"을 뜻하는 아주 범용적인 단어다.
  * 웹이든, 엑셀이든, 스마트폰 앱이든 데이터를 다루는 곳이라면 어디서나 쓰이는 **본질적인 행위**를 말한다.
* **HTTP 메서드 (기술적 용어 / 네트워크 통신 관점):**
  * 프론트엔드(화면)가 백엔드(서버)에게 **"이 데이터를 어떻게 해달라"고 요청할 때 사용하는 인터넷 통신 규칙(동사)**이다.
  * 웹 브라우저와 서버가 대화할 때 사용하는 실질적인 명령어다.



---

## 2. CRUD: 데이터 처리의 4대장
데이터베이스(DB)나 시스템 내부에서 데이터의 생애 주기를 표현하는 단어다.

1. **C (Create - 생성):** 새로운 데이터를 만든다. (예: 회원가입, 새 글 작성)
2. **R (Read - 조회/읽기):** 기존 데이터를 읽어온다. (예: 게시판 목록 보기, 내 정보 확인)
3. **U (Update - 수정):** 기존 데이터의 내용을 고친다. (예: 비밀번호 변경, 글 수정)
4. **D (Delete - 삭제):** 기존 데이터를 지운다. (예: 회원 탈퇴, 글 삭제)

---

## 3. HTTP 메서드: 웹에서의 5가지 행동 지시
프론트엔드가 백엔드 API를 호출할 때, "어떤 목적"으로 호출하는지 명확히 밝히기 위해 사용하는 규약이다. (RESTful API의 핵심)

1. **POST (생성해 줘):** * 목적: 서버에 새로운 데이터를 등록할 때 사용.
   * 특징: 데이터가 주소창에 보이지 않고, 안전하게 내부에 숨겨져서 전달됨.
2. **GET (가져와 줘):** * 목적: 서버에서 데이터를 조회해서 가져올 때 사용.
   * 특징: 주소창에 요청 내용이 그대로 노출됨. (예: `?search=웹개발`) 데이터를 변경하지 않으므로 여러 번 호출해도 안전함.
3. **PUT (통째로 덮어씌워 줘):** * 목적: 기존 데이터를 수정할 때 사용.
   * 특징: 데이터의 **전체**를 교체할 때 쓴다. (예: 회원 정보 전체를 새로 입력받아 업데이트)
4. **PATCH (일부만 수정해 줘):** * 목적: 기존 데이터 중 **일부**만 수정할 때 사용. (예: 회원 정보 중 '비밀번호'만 변경)
5. **DELETE (지워 줘):** * 목적: 서버에 있는 특정 데이터를 삭제할 때 사용.

## 💡 한눈에 보는 매칭 테이블 (CRUD vs HTTP vs SQL)

웹 서비스가 굴러가는 전체 흐름을 보면 이 세 가지 언어가 다음과 같이 맞물려 돌아간다.

| 목적 (행동) | 일반적 개념 (CRUD) | 웹 통신 요청 (HTTP Method) | DB 조작 명령어 (SQL) |
| :--- | :--- | :--- | :--- |
| **새로 만들기** | **C**reate | **POST** | `INSERT` |
| **가져와서 보기** | **R**ead | **GET** | `SELECT` |
| **내용 고치기** | **U**pdate | **PUT** / **PATCH** | `UPDATE` |
| **아예 지우기** | **D**elete | **DELETE** | `DELETE` |

**예시 시나리오 (게시판 글쓰기):**
1. 사용자가 글을 쓰고 '등록'을 누른다. **(Create하려는 목적)**
2. 프론트엔드는 백엔드 서버로 **POST** 요청을 보낸다.
3. 백엔드는 DB에 접속해 **INSERT** 명령어로 데이터를 저장한다.
