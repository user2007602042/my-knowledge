#개발기초 

단순한 화면(프론트엔드)을 넘어, 파이썬(Python)을 활용해 데이터를 처리하고 외부와 통신하는 진짜 '소프트웨어'를 기획하기 위해 반드시 알아야 하는 심화 개념들을 정리한다.

## 1. 객체지향 프로그래밍 (OOP) : 레고 블록 조립하기
과거에는 코드를 위에서 아래로 순서대로만 길게 작성했다(절차지향). 하지만 현대의 파이썬이나 자바(Java) 같은 언어는 모든 기능과 데이터를 독립된 **'객체(Object, 부품)'**로 만들어서 조립하는 방식을 쓴다.

* **클래스 (Class) = 붕어빵 틀 (설계도):**
    * **개념:** 아파트를 짓기 위한 '표준 평면도'. 실제 존재하는 건물이 아니라 "방 3개, 화장실 2개"라는 기본 틀만 정의해 둔 것이다.
* **인스턴스 (Instance / Object) = 구워진 붕어빵 (실제 건물):**
    * **개념:** 위에서 만든 평면도(클래스)를 바탕으로 실제 땅에 지어 올린 '101동 201호', '102동 301호'다. 설계도는 하나지만, 실제 건물(객체)은 무한대로 찍어낼 수 있다.
* **상속 (Inheritance) :**
    * **개념:** 기존 설계도를 그대로 물려받아(상속) 조금만 고쳐 쓰는 기능. "기본 아파트 도면을 그대로 쓰되, 꼭대기 층만 펜트하우스로 변경해서 새로운 도면을 만들어라!"라는 뜻이다. 코드를 처음부터 다시 짤 필요가 없어 효율이 엄청나다.


## 2. 네트워크와 프로토콜 (Protocol) : 데이터의 배달 규칙
프론트엔드(화면)와 백엔드(서버)가 서로 데이터를 주고받으려면 엄격한 '규칙'이 필요하다. 

* **프로토콜 (통신 규약):** 현장에서 본사로 공문을 보낼 때 반드시 '정해진 결재 양식'에 맞춰 보내야 처리해 주는 것과 같은 원리다.
* **HTTP (HyperText Transfer Protocol):** 웹사이트에서 가장 많이 쓰는 전 세계 공통 공문 양식. 인터넷 주소창 맨 앞의 `http://`가 바로 "나는 HTTP 규약에 맞춰서 데이터를 요청할게!"라는 뜻이다.

### 💡 API 호출의 2가지 핵심 방식 (GET vs POST)
바이브코딩 시 AI 에이전트에게 "데이터를 어떻게 처리할지" 지시할 때 반드시 구분해서 써야 하는 핵심 개념이다.

* **GET 방식 (조회/검색):** 데이터를 단순히 **'가져올 때'** 쓴다.
  * *현장 비유: "오늘자 감리 지침서 목록 좀 보여줘."*
  * *특징: 주소창에 내가 검색한 단어가 그대로 노출된다. (보안에 취약하지만 빠름)*
* **POST 방식 (저장/생성):** 새로운 데이터를 서버에 **'밀어 넣을 때'** 쓴다.
  * *현장 비유: "방금 작성한 현장 점검 결과 보고서를 DB 창고에 새롭게 등록(저장)해 줘."*
  * *특징: 데이터가 주소창에 보이지 않고, 편지봉투(Body) 안에 안전하게 숨겨져서 전달된다.*


## 3. 형상 관리 (Configuration Management) : 도면 버전 통제
프로젝트를 진행하면서 수시로 바뀌는 소스 코드와 설계 도면의 **'변경 이력(버전)'을 체계적으로 추적하고 통제하는 활동**이다. (대표적인 프로그램: Git)

* **왜 필요할까?** 여러 명의 작업자가 동시에 도면을 수정하다가 덮어쓰거나, 과거 승인받았던 도면을 분실하는 대참사를 막기 위함이다.
* **베이스라인 (Baseline):** 설계 변경 시 기준이 되는 **'공식적으로 승인된 도면 상태'**. 이 베이스라인이 한 번 정해지면, 이후의 변경 사항은 철저한 심사를 거쳐서만 수정할 수 있다.
