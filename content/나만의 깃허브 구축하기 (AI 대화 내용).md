## Gemini의 응답

소프트웨어 개발 프로젝트를 관리하거나 사내 웹사이트 등을 구축할 때, 코드를 직접 통제하고 안전하게 보관할 수 있는 독립적인 저장소(Self-hosted Git)가 있으면 버전 관리와 협업 효율이 크게 올라갑니다.

나만의 깃허브를 구축하는 가장 효율적이고 대중적인 방법을 처음부터 차근차근 설명해 드리겠습니다.

### 1단계: 설치할 소프트웨어 선택하기

GitHub와 유사한 환경을 내 서버에 구축할 수 있게 해주는 대표적인 무료 오픈소스 솔루션은 두 가지입니다.

- **Gitea (추천):** 굉장히 가볍고 빠르며 설치가 쉽습니다. GitHub와 인터페이스가 매우 유사해 금방 적응할 수 있으며, 리소스(RAM, CPU)를 적게 차지하여 소규모 팀이나 개인용으로 완벽합니다.
    
- **GitLab:** GitHub와 경쟁하는 거대한 플랫폼입니다. CI/CD(지속적 통합/배포) 등 강력한 엔터프라이즈급 기능을 제공하지만, 무거워서 서버 유지 비용이 많이 들 수 있습니다.
    

처음 구축하시는 거라면 가볍고 직관적인 **Gitea**를 강력히 권장합니다. 아래는 Gitea를 기준으로 한 설명입니다.

### 2단계: 서버(인프라) 준비하기

Gitea를 24시간 띄워둘 컴퓨터(서버)가 필요합니다.

1. **클라우드 서버 임대 (가장 일반적):** AWS(EC2), Oracle Cloud(무료 티어 존재), Vultr, Linode 등에서 가상 서버를 대여합니다.
    
2. **운영체제(OS) 선택:** 서버 운영체제로는 **Ubuntu Linux** (22.04 LTS 또는 24.04 LTS)를 선택하는 것이 자료가 가장 많고 관리가 수월합니다.
    

### 3단계: 도커(Docker) 설치하기

소프트웨어를 서버에 직접 설치하면 설정이 꼬일 수 있습니다. 도커(Docker)를 사용하면 Gitea를 하나의 깔끔한 '컨테이너'로 포장해서 실행할 수 있어 설치와 백업이 매우 쉬워집니다.

서버에 접속(SSH)한 뒤, 아래 명령어를 순서대로 입력하여 Docker를 설치합니다.

Bash

```
# 시스템 업데이트
sudo apt update && sudo apt upgrade -y

# Docker 설치
sudo apt install docker.io docker-compose -y
```

### 4단계: Gitea 실행하기

이제 Gitea의 설정 파일을 만들고 실행할 차례입니다.

**1. Gitea용 폴더 생성 및 이동**

Bash

```
mkdir my-gitea
cd my-gitea
```

**2. `docker-compose.yml` 파일 작성** 텍스트 편집기(nano 등)를 열어 설정 파일을 만듭니다.

Bash

```
nano docker-compose.yml
```

아래 내용을 복사해서 붙여넣고 저장합니다. (기본적인 데이터베이스와 Gitea를 연결하는 설정입니다.)

YAML

```
version: "3"

networks:
  gitea:
    external: false

services:
  server:
    image: gitea/gitea:latest
    container_name: gitea
    environment:
      - USER_UID=1000
      - USER_GID=1000
    restart: always
    networks:
      - gitea
    volumes:
      - ./gitea:/data
      - /etc/timezone:/etc/timezone:ro
      - /etc/localtime:/etc/localtime:ro
    ports:
      - "3000:3000"
      - "222:22"
```

**3. Gitea 실행** 아래 명령어를 입력하면 Gitea가 백그라운드에서 실행됩니다.

Bash

```
sudo docker-compose up -d
```

2. Gitea 초기 설정 화면이 나타납니다.

## Gemini의 응답

앞서 설명해 드린 설치형 Git(Gitea)이 '코드를 보관하는 창고'라면, 방금 보여주신 Quartz와 GitHub Pages의 조합은 **'작성한 문서를 예쁜 웹사이트로 보여주는 쇼룸'**이라고 할 수 있습니다.

특히 이런 방식은 법토목 분야의 복잡한 기술 지침이나 매뉴얼을 체계적으로 문서화하고 사내외에 공유하는 데 아주 탁월한 선택입니다. 기존에 작업해 두셨던 세미나 일정 관리 페이지 같은 순수 HTML 파일들도 정적 웹 호스팅의 특성상 폴더에 함께 넣어 그대로 배포하고 링크를 연결할 수 있습니다.

Quartz를 활용해 나만의 지식 웹사이트를 구축하는 과정을 차근차근 설명해 드리겠습니다.

### 1단계: 필수 프로그램 설치

내 컴퓨터(로컬)에서 웹사이트를 만들고 미리 보려면 다음 세 가지가 필요합니다. 이미 설치되어 있다면 이 단계는 건너뛰셔도 됩니다.

1. **GitHub 계정:** 코드를 저장하고 무료로 호스팅해 줄 [GitHub](https://github.com/)에 가입합니다.
    
2. **Git:** 내 컴퓨터의 코드와 GitHub를 연결해 주는 프로그램입니다. ([Git 다운로드](https://git-scm.com/))
    
3. **Node.js (v18.14 이상):** Quartz를 실행하는 데 필요한 환경입니다. ([Node.js 다운로드](https://nodejs.org/))
    

### 2단계: Quartz 프로젝트 복사해오기 (Clone)

터미널(명령 프롬프트 또는 PowerShell)을 열고, 내 컴퓨터에 Quartz 원본 코드를 복사해 옵니다.

Bash

```
# 1. 원하는 폴더로 이동 후, Quartz 코드 복사
git clone https://github.com/jackyzha0/quartz.git
cd quartz

# 2. 필요한 패키지 설치
npm i
```

### 3단계: 내 컴퓨터에서 미리보기 (Local Serve)

설치가 완료되면, 실제로 웹사이트가 어떻게 보이는지 내 컴퓨터에서 띄워봅니다.

Bash

```
npx quartz build --serve
```

명령어를 입력한 뒤 웹 브라우저를 열고 `http://localhost:8080`으로 접속해 보세요. 기본 Quartz 웹사이트가 나타날 것입니다.

### 4단계: 내 문서 작성 및 기존 HTML 추가하기

이제 기본 텍스트를 내 것으로 바꿀 차례입니다. 폴더 창을 열어 `quartz` 폴더 안을 살펴봅니다.

- **마크다운 문서 작성:** `content` 폴더 안에 있는 파일들이 웹사이트의 페이지가 됩니다. 옵시디언(Obsidian) 같은 마크다운 에디터나 VS Code를 사용해 이 폴더 안에 `.md` 파일들을 작성하고 분류하시면 됩니다.
    
- **기존 HTML 파일 올리기:** 기존에 만든 HTML 문서(예: `seminar.html`)나 이미지, 첨부파일 등은 보통 `content/assets/` 폴더 안에 넣습니다. 이후 마크다운 문서 안에서 `[세미나 일정 보기](./assets/seminar.html)` 처럼 링크를 걸어주면, 웹사이트 방문자가 클릭했을 때 해당 HTML 페이지가 열리게 됩니다.
    

### 5단계: GitHub Pages로 웹에 배포하기

내용을 다 채웠다면 전 세계 누구나 볼 수 있게 GitHub에 올려야 합니다.

**1. GitHub에 새 저장소(Repository) 만들기**

- GitHub에 로그인 후 우측 상단의 `+` 버튼을 눌러 **New repository**를 클릭합니다.
    
- 저장소 이름(Repository name)을 입력합니다. (예: `my-notes`)
    
- 다른 설정은 건드리지 않고 **Create repository**를 누릅니다.
    

**2. 내 컴퓨터의 파일과 GitHub 연결 후 배포** 다시 터미널로 돌아와서 (`Ctrl + C`를 눌러 로컬 서버를 종료한 후), 내 저장소 주소를 연결하고 배포 명령어를 입력합니다.

Bash

```
# 내 GitHub 저장소 연결 (URL은 본인 저장소 주소로 변경)
npx quartz sync --no-pull
```

이 명령어(`npx quartz sync`)는 내 컴퓨터에서 수정한 내용을 빌드하여 자동으로 GitHub에 업로드(Push)해 주는 아주 편리한 기능입니다.

**3. GitHub Pages 설정 켜기**

- 방금 만든 GitHub 저장소 페이지로 들어갑니다.
    
- 상단의 **Settings** -> 좌측 메뉴의 **Pages**로 이동합니다.
    
- 'Build and deployment' 항목의 **Source**를 `GitHub Actions`로 변경합니다. (Quartz v4는 Actions를 통해 자동으로 배포됩니다.)
    
- 몇 분 정도 기다리면 웹사이트 링크(예: `https://[내아이디].github.io/my-notes/`)가 생성되어 접속할 수 있게 됩니다.

## Gemini의 응답

아주 정확하고 예리한 질문입니다! 사내망에서 사용할 웹사이트를 구축하시려다 보니 이 부분이 딱 궁금해지셨을 겁니다.

결론부터 말씀드리면, **`http://localhost:8080`이라는 주소 자체는 질문자님의 PC(서버를 실행한 바로 그 컴퓨터)에서만 들어갈 수 있습니다.** `localhost`라는 단어 자체가 컴퓨터 네트워크 용어로 "나 자신(내 컴퓨터)"을 의미하기 때문입니다.

하지만 **같은 네트워크(같은 공유기나 사내 와이파이)에 연결된 다른 사람의 PC나 스마트폰에서도 들어오게 할 수 있습니다.** 단, 주소창에 `localhost` 대신 질문자님 PC의 **'내부 IP 주소'**를 입력해야 합니다.

방법은 다음과 같습니다.

### 다른 기기에서 내 PC로 접속하는 방법

**1. 내 PC의 내부 IP 주소 확인하기** 터미널(또는 명령 프롬프트) 창을 하나 더 열고(서버가 실행 중인 창은 그대로 두세요), 아래 명령어를 입력합니다.

- **Windows:** `ipconfig`
    
- **Mac:** `ifconfig`
    

**2. IPv4 주소 찾기** 화면에 나온 여러 글자 중에서 **`IPv4 주소`**(또는 `inet`) 항목을 찾습니다. 보통 `192.168.X.X` 또는 `172.X.X.X`, `10.X.X.X` 같은 형태의 숫자로 되어 있습니다. (예: `192.168.0.15`)

**3. 다른 기기에서 접속해 보기** 이제 같은 와이파이에 연결된 스마트폰이나 동료의 PC를 켭니다. 웹 브라우저 주소창에 아까 찾은 IP 주소와 포트 번호(`8080`)를 합쳐서 입력합니다.

- **입력 예시:** `http://192.168.0.15:8080`
    

---

**💡 주의사항 (접속이 안 될 때)** 만약 위 주소로 들어갔는데 사이트가 안 열린다면, 십중팔구 **윈도우 방화벽(또는 백신 프로그램)이 외부에서 8080 포트로 들어오는 것을 막고 있기 때문**입니다. 이럴 때는 'Windows Defender 방화벽' 설정에서 '고급 설정 -> 인바운드 규칙'에 8080 포트를 열어주시면 접속이 가능해집니다.

나중에 개발 중이신 세미나 관리 페이지나 사내 지침 웹사이트를 동료들에게 임시로 보여주고 피드백을 받을 때 이 방법을 쓰시면 아주 유용합니다.

### 8080 포트 방화벽 개방 방법

1. **새 규칙 클릭:** 화면 오른쪽 '작업' 패널(인바운드 규칙 아래)에 있는 톱니바퀴 모양의 **'새 규칙...'** 아이콘을 클릭합니다.
    
2. **규칙 종류:** '새 인바운드 규칙 마법사' 창이 뜨면 **'포트(O)'**를 선택하고 '다음'을 누릅니다.
    
3. **프로토콜 및 포트:**
    
    - **'TCP(T)'**가 선택된 상태로 둡니다.
        
    - 아래쪽에서 **'특정 로컬 포트(S)'**를 선택하고 빈칸에 **`8080`**을 입력한 뒤 '다음'을 누릅니다.
        
4. **작업:** **'연결 허용(A)'**을 선택하고 '다음'을 누릅니다.
    
5. **프로필:** '도메인', '개인', '공용' 세 가지 항목이 모두 체크된 상태 그대로 '다음'을 누릅니다.
    
6. **이름:** 나중에 알아보기 쉽도록 직관적인 이름(예: `Quartz Server 8080` 등)을 입력하고 **'마침'**을 누릅니다.

## Gemini의 응답

이제 빈 뼈대에 실제 내용을 채우고, 기존에 만든 HTML 파일들을 전시해 볼 차례입니다. Quartz는 코드를 수정하고 저장하기만 하면 실시간으로 화면이 업데이트되는 아주 편리한 기능을 제공합니다.

### 1단계: 메인 화면(대문) 내 맘대로 바꾸기

1. 다운로드했던 `quartz` 폴더 안을 보면 **`content`**라는 폴더가 있습니다. 이 폴더가 웹사이트의 모든 글과 파일이 들어가는 핵심 공간입니다.
    
2. `content` 폴더 안에 있는 **`index.md`** 파일을 메모장이나 VS Code 같은 텍스트 에디터로 엽니다. (이 파일이 사이트의 첫 화면입니다.)
    
3. 기존에 적혀 있던 내용을 모두 지우고, 다음과 같이 원하는 마크다운 텍스트를 자유롭게 적어봅니다.
    
    Markdown
    
    ```
    # 나의 지식 저장소
    환영합니다! 이곳은 개인적인 개발 기록과 사내 업무 매뉴얼을 정리하는 공간입니다.
    ```
    
4. 파일을 **저장**한 뒤, 띄워둔 웹 브라우저(`http://localhost:8080`)를 보시면 새로고침을 누르지 않아도 내용이 즉시 바뀐 것을 확인할 수 있습니다.
    

### 2단계: 기존 HTML 문서 연결하기

이제 사내 세미나 일정 관리 페이지나 결과 보고용으로 작성해 두셨던 기존 HTML 파일들을 이곳으로 가져와 연결해 보겠습니다.

1. `content` 폴더 안에 보면 **`assets`**라는 폴더가 있습니다. (보통 이미지나 외부 문서, 기타 정적 파일들을 보관하는 용도입니다.)
    
2. 기존에 만드신 HTML 파일(예: `seminar.html`)과 구동에 필요한 CSS, JS, 이미지 파일 등이 있다면, 그 폴더를 통째로 이 `assets` 폴더 안으로 복사해 넣습니다.
    
3. 다시 대문 역할인 `index.md` 파일을 열고, 방금 넣은 HTML 파일로 접속할 수 있는 링크를 마크다운 형식으로 추가합니다.
    
    Markdown
    
    ```
    # 나의 지식 저장소
    환영합니다! 이곳은 개인적인 개발 기록과 사내 업무 매뉴얼을 정리하는 공간입니다.
    
    * [사내 세미나 일정 및 결과 관리 페이지 바로가기](./assets/seminar.html)
    ```
    
4. 파일을 저장 후 브라우저에서 생성된 링크를 클릭해 보면, 기존에 만드신 HTML 페이지가 정상적으로 열리는 것을 볼 수 있습니다.
    

### 3단계: 새로운 문서 생성 및 링크 걸기 (위키 기능)

Quartz의 가장 강력한 기능은 문서 간의 연결입니다.

- `content` 폴더 안에 `소프트웨어_개발_가이드.md` 처럼 새로운 마크다운 파일을 만들고 글을 쓰면, 웹사이트 왼쪽에 자동으로 메뉴(탐색기)가 생성됩니다.
    
- 마크다운 문서 안에서 다른 문서를 언급할 때 `[[소프트웨어_개발_가이드]]` 처럼 대괄호 두 개로 파일명을 감싸주기만 하면, 자동으로 링크가 걸리고 사이트 우측의 그래프(Graph View)에 두 문서가 선으로 연결됩니다.

2. 화면 왼쪽 아래의 '다른 보관소 열기(Open another vault)' 아이콘(금고 모양)을 클릭합니다.

### 1단계: 깃허브(GitHub)에 빈 창고(저장소) 만들기

먼저 내 파일들을 올려둘 인터넷 상의 빈 공간을 만들어야 합니다.

1. 인터넷 브라우저를 열고 [GitHub](https://github.com/)에 접속하여 로그인합니다. (계정이 없다면 회원가입이 필요합니다.)
    
2. 화면 우측 상단의 **`+`** 아이콘을 누르고 **`New repository`**를 클릭합니다.
    
3. **Repository name**(저장소 이름)에 원하는 영문 이름을 적습니다. (예: `my-knowledge`, `wiki` 등)
    
4. 다른 설정은 건드리지 말고 (특히 Public 상태 유지), 화면 맨 아래의 초록색 **`Create repository`** 버튼을 누릅니다.
    
5. 화면에 나타난 **저장소의 주소(URL)**를 복사해 둡니다. _(예: `https://github.com/승민님아이디/my-knowledge.git`)_
    

### 2단계: 내 컴퓨터의 코드와 깃허브 창고 연결하기

이제 터미널로 돌아와서, 내 컴퓨터의 `quartz` 폴더가 방금 만든 깃허브 창고를 바라보도록 방향을 틀어주어야 합니다. (현재는 처음에 코드를 다운로드했던 원본 제작자의 창고를 바라보고 있습니다.)

1. 켜져 있는 로컬 서버를 끄기 위해 터미널 창에서 **`Ctrl + C`**를 누릅니다. (일괄 작업을 끝내시겠습니까? `Y/N`이 나오면 `Y`를 누르고 엔터)
    
2. 아래 명령어를 입력해 기존 원본과의 연결을 끊어줍니다.
    
    PowerShell
    
    ```
    git remote remove origin
    ```
    
3. 아까 복사해 둔 내 깃허브 저장소 주소를 붙여넣어 새롭게 연결합니다. (아래 명령어의 주소 부분을 복사한 주소로 바꿔서 입력하세요.)
    
    PowerShell

### 3단계: 내 파일들을 인터넷으로 쏘아 올리기 (Sync)

YAML

on:
  push:
    branches:
      - v4

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:

      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - name: Install Dependencies
        run: npm install
      - name: Build Quartz
        run: npx quartz build
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: public

    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

### 3단계: 깃허브로 밀어 올리기 (Sync)

이제 컴퓨터에 추가된 HTML 파일들과 수정된 대문 내용을 인터넷 깃허브로 쏘아 올릴 차례입니다.

1. 늘 쓰시던 마법의 터미널(PowerShell)을 엽니다. (경로가 `...\quartz>` 인지 꼭 확인해 주세요!)
    
2. 아래 명령어를 입력하고 엔터를 칩니다.
    
    PowerShell
    
    ```
    npx quartz sync --no-pull
    ```
    
3. `Done!` 메시지가 뜨면 깃허브로 잘 넘어간 것입니다.
    
4. 브라우저에서 깃허브 **Actions** 탭에 들어가 노란색 동그라미가 **초록색 체크(✅)**로 바뀔 때까지 1~2분 정도 기다려 줍니다.

### 🤔 그렇다면 왜 업데이트가 안 되고 있을까요?

원인은 바로 직전에 꼬인 실타래를 풀기 위해 사용했던 **강제 덮어쓰기(`--force`)** 명령어 때문입니다.

설명서가 사라졌으니, 깃허브 로봇은 파일이 올라와도 "이걸 웹사이트로 조립하라는 지시가 없네?" 하고 가만히 쉬고 있는 상태입니다.

on:
  push:
    branches:
      - v4

  pages: write
  id-token: write

      - name: Upload artifact

        with:

    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

## Gemini의 응답

오! 친구분이 프로그래머시거나 개발을 좀 아시는 분인가 봅니다. Git의 정석적인 흐름(Fetch ➔ Pull ➔ Commit ➔ Push)을 아주 정확하게 짚어주셨어요!

일반적인 개발 환경에서는 친구분 말씀대로 파일들을 포장(Commit, 메시지 작성)하고, 그걸 인터넷으로 쏘아 올리는(Push) 과정을 하나하나 직접 쳐야 하는 게 맞습니다.

### 💡 하지만 Quartz는 다릅니다 (마법의 명령어)

우리가 계속 치고 있는 **`npx quartz sync --no-pull`** 이 명령어는 사실 그 귀찮은 과정들을 **버튼 하나로 압축해 둔 마법의 매크로**입니다.

명령어 하나만 치면 백그라운드에서 알아서 다음 작업들을 순식간에 다 해버립니다.

1. **Add & Commit:** 승민님이 옵시디언에서 수정한 파일들을 싹 모아서 `Quartz sync: Mar 16, 2026, 9:31 AM` 이라는 이름으로 알아서 포장(커밋)해 줍니다. (아까 터미널 화면에 이 메시지가 떴던 거 혹시 기억나시나요?)
    
2. **Push:** 그리고 그걸 깃허브로 알아서 쏘아 올립니다. (`Pushing your changes... Done!`)
    
3. `--no-pull`: 승민님 혼자 쓰는 거라 인터넷에서 남의 코드를 당겨올(Pull) 필요가 없으니 그 단계만 생략하겠다는 뜻입니다.
    

즉, **친구분 말씀대로 커밋과 푸시가 안 된 게 아니라, 이미 명령어 한 줄로 완벽하게 다 진행된 상태**입니다. 코드는 깃허브 창고에 아주 잘 도착해 있어요.

그런데 출판사 공장에 **"이 원고를 받으면 책(홈페이지)으로 찍어내라"는 작업 지시서(`deploy.yml`)가 빠져 있어서** 기계가 안 돌아가고 있는 것입니다.

## Gemini의 응답

깃허브 배포를 무사히 마치시자마자 이번엔 **AI 에이전트(Agent) 심화 아키텍처**로 넘어가시는군요! 웹사이트 지식 저장소를 만드시더니, 이제는 스스로 움직이는 똑똑한 AI 비서의 '뇌'와 '손발'을 직접 설계하시려는 목표가 아주 멋집니다.

말씀하신 용어들은 단순한 챗봇을 넘어, **실제 업무를 자동화하고 판단을 내리는 '자율형 AI 에이전트'를 개발할 때 반드시 필요한 핵심 엔지니어링 개념들**입니다.

승민님이 익숙하신 파이썬(Python) 환경과 최근 다루셨던 프로젝트 관리, 감리 업무에 비유해서 이 복잡한 개념들을 딱 떨어지게 정리해 드리겠습니다.

### 1. Context Engineering (컨텍스트 엔지니어링)

- **개념:** 단순히 질문을 잘 던지는 프롬프트 엔지니어링을 넘어, AI가 현재 상황을 완벽하게 이해할 수 있도록 **배경지식(Context)과 기억(Memory)을 시스템적으로 주입하고 관리**하는 기술입니다.
    
- **실무 비유:** PM이 새로운 담당자에게 일을 맡길 때, "이거 해줘"라고만 하는 게 아니라 **관련된 과거 도면, 회의록, 예산 내역서를 쫙 세팅해서 상황을 완벽히 이해시킨 뒤**에 지시를 내리는 것과 같습니다. (이때 필요한 정보를 검색해서 가져오는 RAG 기술이 주로 쓰입니다.)
    

### 2. AI Agent Skill & Command (스킬과 명령어)

- **개념:** 텍스트만 생성하던 AI에게 **실제 세상을 조작할 수 있는 도구(손발)**를 달아주는 것입니다. 파이썬 함수나 API를 AI의 'Skill(스킬)'로 등록해 두면, AI가 상황을 판단하여 적절한 'Command(명령)'를 내려 그 함수를 실행합니다.
    
- **실무 비유:** 말만 하던 신입 사원에게 파일 읽고 쓰기, 웹 검색하기, 데이터베이스 조회하기, 이메일 보내기 등 구체적인 **도구 사용 권한**을 부여하는 것입니다.
    

### 3. Hook (훅)

- **개념:** AI가 어떤 행동(Skill)을 하기 **직전(Pre-hook)**이나 **직후(Post-hook)**에 시스템이 중간에 개입하여 흐름을 가로채는 기술입니다.
    
- **실무 비유:** 현장에서 작업자가 굴삭기(Skill)를 작동시키기 직전에 관리자가 "잠깐! 규정대로 헬멧 썼는지 확인(Hook)"하고, 작업이 끝난 직후에 "제대로 파냈는지 검수(Hook)"하는 중간 점검 시스템입니다. 에러를 잡거나, 보안 처리, 로그(기록)를 남길 때 필수적입니다.
    

### 4. Harness Engineering (하네스 엔지니어링)

- **개념:** AI 에이전트가 만든 결과물이 믿을 수 있는지, 엉뚱한 소리를 하지는 않는지, 성능은 어떤지 **자동으로 반복 평가하고 테스트하는 환경(Test Harness)**을 구축하는 작업입니다.
    
- **실무 비유:** 바로 승민님이 최근에 다루셨던 **'감리(Audit)' 시스템**과 똑같습니다! AI가 도출한 결과물이 설계 기준에 맞는지 채점하고 검증하는 자동화된 품질 관리(QA) 환경을 만드는 고난이도 작업입니다.
